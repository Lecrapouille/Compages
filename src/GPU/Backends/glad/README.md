# glad

Vendored OpenGL function loader, generated by [glad2](https://github.com/Dav1dde/glad).

It is committed rather than downloaded so that building the project needs no network access and no code generation step.

## Why it is vendored here and not in external/

`external/external.mk` declares the dependencies fetched by MyMakefile. glad is different: it is generated output, tied to the OpenGL version the backends target. It therefore sits beside the backends that use it: `GL45/` and `GL41/` on the desktop. The `GLES3` build (WebGL 2) does not use it: its symbols come from `GLES3/gl3.h` and the linker.

## Regenerating

```bash
python3 -m venv /tmp/gladenv
/tmp/gladenv/bin/pip install glad2
/tmp/gladenv/bin/python -m glad --api gl:core=4.6 --extensions "" \
    --out-path /tmp/gladout c --loader
cp /tmp/gladout/include/glad/gl.h         include/glad/
cp /tmp/gladout/include/KHR/khrplatform.h include/KHR/
cp /tmp/gladout/src/gl.c                  src/
```

The generated `gl.c` is copied as `gl.cpp`. glad's output is written to be valid in both languages, and building it as C++ means the whole project is compiled with one set of flags: the C compiler was otherwise warning about the C++ options it was being handed.

`--extensions ""` asks for no extension at all: everything this backend needs is in core 4.6. Keeping the extension list empty is what keeps the generated files small.

## Current version

- glad 2.0.8
- Specification: `gl`, API `gl:core=4.6`, no extensions

## Note on the OpenGL version

The loader is generated for 4.6. `gladLoadGL()` loads only what the context gives, so the same loader serves the `GL45` backend (which refuses less than 4.5) and the `GL41` backend (4.1, the last version of macOS). See `doc/concepts/architecture.md`.
